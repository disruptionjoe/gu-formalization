# GU functional-channel operating contract v1.0

## Outcome

GU keeps its purpose-bearing Lanes 1, 2, 3 and A. Work inside those Lanes is
now routed through four functional channels: **Build, Compose, Source and
Verify**. The channels do not create new scientific lanes and do not replace
the repository portfolio. They make the method of reaching a Lane outcome
explicit.

The conditional-physics ledger is the standing compositional deliverable and
progress meter. Construction is not complete merely because its target set is
fully typed. Progress means that coverage is honest, row distances or residue
fall, a prediction becomes sharper, or a scoped adverse result rules out a
route. Coverage rising with unchanged residue is visible mapping work, not a
claim that GU is converging physically.

`lab/process/conditional-physics-ledger-v0.28.json`, paired with
`explorations/conditional-build/conditional-physics-ledger-v0.28.md`.

## The four channels

### Build

Build constructs or varies a mathematical object against named ledger rows.
It starts from the typed object and its source/geometry owner, not from a
generic wish to harden the repository.

A Build output succeeds by doing at least one of the following:

- reducing a row's `distance` or the global residue;
- supplying a missing map, action term, quotient, domain or datum;
- sharpening a prediction or kill condition;
- proving a scoped no-go and naming the nearest constructive replacement; or
- discovering that the target was mistyped and returning it to Compose.

Every Build wave declares its ledger rows before computation and emits the
current ledger meter plus the rows' before/after states. If no row changes, it
must say `ledger_row_changes: none` and give an evidence-backed reason. Build
does not infer physical recovery from carrier containment or familiar names.

### Compose

Compose owns the denominator, aliases, migration edges, row typings,
reason-kind taxonomy, progress meter, residue inventory, contradiction
discovery and cross-composition of already established results. It is a
first-class deliverable, not spare-cycle support for Build.

Compose succeeds when it adds a target at grade, raises honest coverage,
changes a row's distance/tightness/residue, finds an over-determined row, or
uses existing evidence to retire, redirect or reduce a Build task. A newly
found over-determined row is valuable even before its disposition.

Rows carry a verdict and an extensible `reason_kind`, plus `distance`,
`revival_trigger`, evidence and mapping grade. A case that fits no existing
kind creates `NEW_KIND_REQUIRED`; forced fitting is forbidden. In particular:

- `SAME` distinguishes derived, conditionally/partially derived, imported and
  put-in agreements;
- `DIFFERS` distinguishes predictions, convention artifacts, inert
  statements, structural differences and killed routes;
- `NEEDS` distinguishes a bit, finite choice, real/integer datum, external
  datum, missing construction, a proven-unsupplyable source, and a construction
  proven unable to close the row in its current action; and
- `OVER_DETERMINED` distinguishes genuine falsification, fork artifact, scope
  error and stale premise.

The finder of an over-determined row escalates it and may not adjudicate it.
An independent owner assigns one of the four dispositions and preserves the
original evidence and migration edge.

Compose runs after three material Build outputs and immediately when any
verdict, residue count, discrete fork, high-fanout premise, source correction
or adverse row changes. This is also the breadth/archaeology checkpoint that
asks whether the repository already solved, superseded or contradicted the
next expensive target.

### Source

Source reconstructs what Weinstein, Curt and other cited sources actually
claim, with timestamp/page, object type, stated role and omissions. A decisive
Eric-lane pass, kill or no-go must record exactly one return:

- `SOURCE-CONFIRMS`: the primary source states the same typed object and
  relation;
- `SOURCE-CORRECTS`: the primary source changes the question, type, fork or
  attribution; or
- `SOURCE-SILENT`: the source does not decide the construction burden.

Source evidence can redirect a construction and correct attribution. It
cannot by itself prove the mathematics, select a datum or promote observed
physics. When a construction hits a failure in the Eric lane, Source checks
the Weinstein material for that exact object before the failure is propagated.

### Verify

Verify attacks new, changed or high-fanout claims. It does not consume a run
by replaying an unchanged packet merely because Build is occupied. Replays are
admitted only for a named integrity risk: a changed dependency, environment,
scope, implementation, result surface or unresolved hostile objection.

Every material claim receives the two-sided hostile review:

1. find where the summary outruns the artifact; and
2. find where a rigorous fence or lane is defending a superseded or mistyped
   object.

Reviews that touch an action, variational map, constraint/BV quotient,
boundary charge, observation descent or claimed physical transition must also
include a symplectic-geometry lens. That reviewer asks whether the candidate
Hamiltonian or current descends to a nonzero class on reduced covariant phase
space after the presymplectic characteristic kernel and exact boundary
generators are quotiented. An unreduced density is not a physical transition.

When the work has substantial specialist judgment, a lightweight divergent
preassessment names the relevant lenses before construction. A separate
sub-agent per persona is not required. Controls verify the stated computation;
Layer 0 verifies that it was the right question.

## Dispatch without percentages

There are no fixed channel percentages. Select the highest-information
eligible condition:

1. If the target object or current premise is semantically/source-uncertain,
   run Source or Compose before Build.
2. If an over-determined row awaits independent disposition and has high
   downstream fanout, adjudicate it before dependent construction.
3. If a typed row has a buildable distance and its premises are current, run
   Build.
4. If three material Build outputs have landed, or a high-fanout fact changed,
   run Compose before another expensive Build.
5. Run Verify on changed/high-fanout claims or a named integrity risk.
6. If a GU writer holds the central claim, another automation may do useful
   read-only Source, Compose or Verify work on a disjoint gate. It may not
   create a competing owner write or call unchanged replay progress.

Construction remains the target. Hardening is scheduled when a construction,
claim transition or publication dependency creates the demand.

## Standing ledger progress surface

The current standing denominator is the append-only conditional-physics
ledger. Its axes are Lagrangian/equation terms, representation requirements and
anomaly/consistency conditions—not particles as a separate counting axis.

Every row-touching wave emits a line of this form from the machine ledger:

```text

SAME · DIFFERS · NEEDS · OVER-DETERMINED
Residue — continuous + function-valued + discrete forks; quotients ranked
```

The ledger is versioned append-only. A new target appends a row and increments
the minor version. A changed meaning creates a successor and migration edge.
Prior verdicts are never silently overwritten. The freshness gate is red when
a Build or Compose result touches a row but neither advances the ledger nor
records an explicit no-change reason.
