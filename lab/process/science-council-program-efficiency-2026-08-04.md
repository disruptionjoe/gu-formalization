## 1. The measure

Joe's correction is adopted and is the primary measure. The earlier framing
("five kills, zero positive constructions") was wrong as accounting: a result of
the form *"X fits, but requires external supply Y"* is a **conditional match with
a named requirement**, and it carries two payloads — a real consistency check
passed, and a partial specification of the missing object.

**PRIMARY MEASURE — specification tightening.** A wave **tightens** when it does
at least one of:

| id | tightening act | exemplar in the window |
|---|---|---|
| (i) | reduces the free-parameter count of a named missing object | DC-H2: A4's residue 3 coefficients → **1** (`dc-h2-...-2026-08-04.md:241`) |
| (ii) | excludes a **class** of candidate suppliers, not a candidate | DC-H2: every blockwise-congruence-invariant condition (`:233`) |
| (iii) | adds a shape constraint the supplier must satisfy | time-orientation: any supplier must be **fibrewise**; base-side supply excluded |
| (iv) | exhibits the receptacle exactly | M-H7: closed, stably parallelizable `L^13`, **non-product** framing, nonzero PT class at stem site `3+10` (`mh7-...:284`, `:307`) |
| (v) | converts an assumption into a derived fact | time-orientation run **derives** the `(6,4)` fibre signature DC-H1 had asserted |

A wave **relocates** when it hands off a gate of comparable size with the same
number of free choices, and **loosens** when it introduces a new un-owned object.

**SECONDARY MEASURE — free-object delta (`F`).** New un-owned/unselected objects
introduced minus retired, per wave. Sustained `F ≥ 0` is the circling signature
and is the one number that cannot be gamed by writing more artifacts.

**CALIBRATION — constrainedness grade.** Per Joe: the value of a conditional
match is how tightly the external requirement is constrained, not that it is
named. This council uses:

| grade | meaning |
|---|---|
| **T4** | full type specified **and** every alternative route exactly excluded — handable to an outside specialist as a construction problem |
| **T3** | type + dimension/units fixed **and** a class of suppliers excluded |
| **T2** | typed, no class exclusion |
| **T1** | named, untyped |
| **T0** | requirement currently met by an unexamined convention |

## 4. Seat 2 — was the conditional pivot correct, and what has not been tried

**Yes, and the chain contains its own proof.** The direct assembly failed because
a functional cannot be written when the carrier's real form, adjoint class, and
codomain are undetermined. Waves C, D, G and K each determined exactly one of
those, and each was necessary. The decisive evidence is Wave K itself: **a direct

**But the shape of the response is incomplete, and Joe's target statement names
the missing half.** Component-mapping without a target ledger has no stopping
rule and no coverage fraction. The correct shape is *component-mapping ordered by
a residue ledger* — map a component because a ledger row needs it, not because it
is next in the chain. §5 develops this.

**Alternatives the program has not tried.** Named as requested; this council
recommends only the first, and only in the bounded form stated.

1. **The deliberately-wrong complete construction ("strawman total action").**
   Stipulate *any* admissible choice at every open fork — real form, `J_red`,
   trace-`q`, `[T,T]` normalization, the `eps` instance, section-vs-observerse —
   assemble the full functional end to end, and vary it. Correctness is not the
   point and no claim is filed. The point is that **a complete object exposes the
   shape of the assembly**: which arrows are load-bearing, which forks actually
   propagate downstream, and where Euler/Ward genuinely breaks. The program has
   never held a complete object. This converts §5's fan-out question from
   inspection into measurement — *change one fork, count the rows that move*.
   Cheap, non-claim-bearing, and the single highest-information untried move.
2. **Work backward from a required output.** Fix one target the construction must
   hit — a massless photon kernel, or the exact Einstein contraction — and derive
   what the action must contain for it to emerge. K77-B3's "restricted-domain
   route" does this locally; it has never been run as a search strategy.
3. **Borrow a construction skeleton from an adjacent theory.** The program has
   done source fidelity (Eric/Curt) thoroughly and adjacent-theory skeletons not
   at all. The closest structural analogue is **MacDowell–Mansouri / Cartan
   first-order gravity**: a connection valued in a larger algebra, with the action

   candidate: the coset-reduction literature for `GL(n,R)/O(p,q)` fibres, which is
   what `Y^14 = Met(X)` is. Third: supergravity's Rarita–Schwinger sector, which is
   literally the spinor-valued-form carrier K77-A confirmed. **Caution:** this is

### 5.4 Ordering, ruled

**Residue-first, with a fan-out override.**

### 5.5 The guard metric, priced against the theatre risk

The risk is real and named correctly: a ledger can grow rows without tightening
anything, and can look like progress while the residue stays constant.

**Guard: publish a three-number tuple in every wave disposition's frontmatter.**

```yaml
residue_count: <number of live column-3 items>
residue_tightness: {T4: n, T3: n, T2: n, T1: n, T0: n}
```

  (Wave H would have fired this; Waves E and F would have flagged.)
- **Genuine convergence** = tightness mass migrating T1→T2→T3→T4 with
  `free_object_delta ≤ 0`.

`residue_count: 5(+), residue_tightness: {T4:1, T3:3, T2:1}, free_object_delta: −1`
over the last four waves. That is the honest number, and it is good.

symmetry condition can supply one; (ii) the repo banks `PRED-NORM-RANK =
RESOLVED_NO_GO`, GU has **no native absolute scale**; therefore the source action
provably requires an **imported** scale — a structural finding rather than a
construction failure.

**Layer-0 typing of the two scales, done first as instructed.**

| | DC-H2's scale | PRED-NORM-RANK's scale |
|---|---|---|
| object | the gimmel metric's **horizontal:vertical relative** scale within `G` on `Y^14` | `μ_DW`, the **overall** DeWitt/gimmel scale, plus the normalization magnitudes `{κ, Z_U}` and `source_norm` |
| type | one length², the fibre radius in base units (`dc-h2:250`) | rank-3 free rescaling on the log-monomial exponent list `{κ, Z_U, μ_DW, m_pole, λ_pole, ρ^¼, source_norm}`; invariant quotient dimension 4 (`pred-norm-rank-2026-07-15.md:44-60`) |
| proof | congruence-orbit argument: the ratio *is* a coordinate on the orbits of the group under which every candidate condition is invariant | log-monomial rank certificate, `tests/normalization-scoping/pred_norm_rank.py`, with five explicit negative controls |
| status | exploration, 2026-08-04 | portfolio state `RESOLVED_NO_GO`, contract-locked at `process_gates/research_portfolio_contract_audit.py:366-376` |

**RULING — three parts.**

**(1) The premise-identification is a SCOPE ERROR.** PRED-NORM-RANK's exponent list
contains **no block ratio**. Its three free rescalings are field normalization
(`κ:+1, Z_U:−1`), DeWitt scale (`μ_DW` and the absolute pole/range/density scales),
and source normalization. The horizontal:vertical *relative* scale within the gimmel
metric is a different coordinate from the *overall* gimmel scale, and the rank-3
certificate does not cover it. So PRED-NORM-RANK does **not** imply DC-H2's residue
is free; DC-H2 proved that independently, by a different argument.

**(2) The conclusion is SOUND but NOT NEW — it is banked twice, since July, and one
of the two is stronger than the syllogism.**
- `PRED-NORM-RANK` itself already states the source-side consequence verbatim: *"No
  invariant basis element contains `source_norm`. Any route that depends on source
  normalization must wait for a native source-normalization rule"* (`:71-72`), and
  its reopen condition is literally "native source dynamics".
- The **H49 Λ-magnitude no-go** is stronger and is COMPUTED, graded settled-FAIL, and
  in a paper: *"a dimensionful `Λ = (dimensionless number) · μ_DW²` requires an
  IMPORTED scale"*, firing as a class-level scope-kill for GU and the entropic
  alternative alike (`tests/wave28/H49_bach_weyl_sector.py:452-476`;
  `papers/candidates/one-residual-complete-picture/...:640-642`).
- The repo has also already named the *unique home* for the import: the B5 global
  datum / spectral-section cut scale, "the one place the frozen material allows an
  absolute scale to enter" (`de-amplitude-audit-2026-07-20.md:72,190-197`).
- And the sibling `du-conditional-composition-audit` (2026-08-04) has **already
  assembled precisely this syllogism** as its D5 and prohibition F7, quoting both
  DC-H2 and PRED-NORM-RANK side by side and concluding that a scale must enter from
  outside all four legs.

**Therefore: filing this as a new structural finding would be exactly the
self-flattering conversion the near-miss council warned against. It is refused.**

**(3) What IS new is a COUNT question, and it is cheap, decidable, and unasked.**
PRED-NORM-RANK's certificate contains its own length² — *"`ℓ² = Z_U·κ` … the product
is **still a free native scale**"* (`:64-72`). DC-H2's residue is also a length².
Nobody has checked whether they are the same object — and DC-H2 does not cite
PRED-NORM-RANK anywhere, while explicitly flagging `Z_U` itself as a **homonym**
(ledger sense = the whole gradient term, NOT BUILT; W229 sense = the scalar
coefficient, `normalization_unbuilt`) at `dc-h2:50`. That is precisely the kind of
homonym the repo's Layer-0 discipline exists to catch, and it is currently uncaught.

> **The unasked question, which this council recommends as the cheapest high-value
> move in the program: is DC-H2's horizontal:vertical length² the same object as
> PRED-NORM-RANK's `ℓ² = Z_U·κ`, or independent of the rank-3 rescaling group?**
>
> - **Same object** ⇒ the rank certificate already covers it; DC-H2 becomes a second
>   independent proof of a banked fact; the program's imported-scale count is
>   unchanged. Clean, and it retires an open worry.
> - **Independent** ⇒ **the rank-3 certificate is INCOMPLETE**, the program's

>   with the block ratio in its exponent list.
>
> Cost: hours. No new geometry. One artifact, exact arithmetic, the existing probe

> genuine defect found in the program's own contract-locked certificate.

**Effect on priorities if run.** It fixes the headline number of column 3 — *how

## 7. Seat 5 — where to point the pre- and post-reviews

Both mechanisms are kept. Neither is relitigated. Both are re-aimed by adding
standing questions that the 2026-08-03/04 evidence shows would have caught the
program's two measured failures.

### PRE-review — add three standing questions

| id | question | what it would have caught |
|---|---|---|
| **PRE-1** | *What discrete Layer-0 fork does this wave assume without deciding, and what does it cost if the other branch is right?* | Wave K. Seven waves of `(9,5)` construction were stacked on an undetermined real-form fork |
| **PRE-2** | *What is the dimension of the candidate space this wave will search, and can it be computed exactly before enumeration?* | The three redundant trace-`q` probes. This is the K77-B3 / Wave G method, promoted to a requirement |
| **PRE-3** | *If this wave succeeds, does it introduce a new un-owned object? Name it and its owner now, or don't introduce it.* | Wave H's `J_red` ("source-silent", still un-owned four waves later) |

PRE-2 has a sharp sub-form that DC-H2 demonstrates and that should be asked whenever
a wave proposes to test a selector: **is the target quantity a coordinate on the
orbits of a group under which all candidate selectors are invariant?** If yes, the
whole class is dead in one theorem and the enumeration is wasted.

### POST-review — keep the hostile lens, add the ledger question

The hostile post-review is demonstrably the highest-value mechanism the program has
and nothing here reduces it. Its catches in this window: Wave I's decisive `O^-T`
vs `O` type error (with a rational mixed-sign boost exhibiting the difference), Wave
J's three retracted claims, Wave H's seven required repairs before `79/79`, K77-A's
material repair and scope narrowing before `103/103`. That is a strong record.

**What it is not currently asked, and should be — two questions, both mechanical:**

| id | question |
|---|---|
| **POST-1** | *Did this wave tighten the specification of a named missing object — (i)–(v) — or relocate it? Emit the `residue_count` / `residue_tightness` / `free_object_delta` tuple.* |
| **POST-2** | *Grade every conditional match this wave touched on T0–T4, and state whether the grade moved.* |

POST-1's tuple is the guard metric of §5.5. Making it a post-review output rather
than a separate bookkeeping task is what keeps it from becoming its own overhead.

**One structural note.** Both mechanisms currently review *waves*. Neither reviews
*the queue*. The wave-K loss was a queue defect, not a wave defect — every individual
wave D–J passed its own review. A quarterly (or per-campaign) **queue review** asking
only PRE-1 across all live forks would have caught it, and nothing in the current
process is positioned to.
