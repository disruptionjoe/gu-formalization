# Layer-0 pass on the 2+1 count claim

Run because Joe flagged that class-relative no-goes have proved unreliable and
the ratified protocol must be used. Loading it surfaced two things I had not
carried: the protocol is **seven axes plus a Layer-0 precondition** (ratified
2026-07-10), not six, and Layer-0 exists precisely to catch the error made here.

## The check

> Do the construction and the no-go MEAN the same object by their shared terms?

**Shared term: "generation count" / "three families."**

| | object denoted |
|---|---|
| `SA-C3`, T1 odd-torsion bar | the **realized chiral index** `ind_H(D_GU)` — an integer, operator-analytic, whose odd part must live in the order-3 element of `pi_3^s` |
| the 2+1 product-rule result | a **multiplicity decomposition** of `ker Gamma` into `384 + 1152 + 128` — representation-theoretic |

**Verdict: `HOMONYM`, false-escape direction (the equivocation trap).**

The decisive in-repo fact is one this session itself established. Rung 1
(`rung1-finite-coefficient-enumeration-2026-07-29`) proved, with controls and a
planted-unbalanced-grading detector, that the net chiral index is a function of
the **grading** and is unmoved by every coefficient in the symmetry-permitted
space. A decomposition of the carrier into three blocks says nothing about the
index: an internally balanced block contributes zero, and three of them
contribute zero.

**So the multiplicity is forced. The index is not.** The T1 bar still bites the
object it was always about.

## What is retracted

**D3 — RETRACTED.** `SA-C3` (the realized chiral rank) is **not** discharged by
the 2+1 result. It remains a DECLARATION. I ranked this the highest-value item
in the term-by-term pass; it was the homonym.

**D4 — WEAKENED.** `SA-C1`'s "carrier B is forced if count-selecting" was said
to lapse because the count comes from the product rule. It does not lapse: the
count in that row is the index, which the product rule does not supply. If
index-selection is still required, B's conditional forcing stands.

**The external-datum ledger — CORRECTED.** Its computation is unchanged and
correct; its verdict label `P3-IS-NOT-EXTERNAL` was the homonym. **P3 is not
withdrawn.** The ledger returns to **three** pieces:

| piece | status after Layer-0 |
|---|---|
| P1 — a `Z/2` orientation | needed; still serves two slots |
| P2 — the X-sector datum | needed; type unknown |
| P3 — the count datum | **reinstated** — the multiplicity result does not reach the index |

## What survives, and why

**D1 — SURVIVES.** The Yukawa texture question is multiplicity-side: `SA-Y4`'s
`9 -> 3` reduction and `SA-Y7a`'s `Z/3` doublet spurion are statements about
flavour structure on the carrier, not about the index. A `2+1` block structure
genuinely bears on them.

**D2 — SURVIVES.** `SA-Y6`'s sector-to-flavour assignment is about whether the
three sectors are distinguishable. The product rule makes one of them
identifiable (non-Leibniz form) independent of any index question. The narrowing
holds.

**The 2+1 structure itself — SURVIVES, unchanged.** Two Leibniz partners plus one
correction term, forced by gamma-tracelessness on even/even splits, with the
traceful control showing the third term vanishes without the gamma-trace
constraint. That computation was never at issue.

## What this cost and what it bought

It cost the session's most exciting-looking claim, which was wrong in the
specific way the protocol is designed to catch, and which I would have carried
into the next run had the protocol not been invoked.

It bought a sharper statement of what `2+1` is actually good for: it constrains
**flavour structure and sector identifiability**, not the count. Those are real
and they are where D1 and D2 live.

## Standing note for future passes

The temptation this pass caught is specific and will recur: **"three blocks"
reads like "three generations."** It is not the same claim unless each block
carries a nonzero chiral index, and Rung 1 says none does at balanced grading.
Any future argument from a decomposition to a count must clear Layer-0 first,
naming which object it means by "count."
